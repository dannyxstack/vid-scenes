# 产品文档：vid-scenes

> 本地视频素材管理 + 音乐卡点视频自动编排工具。目标是搭建一条类似 YouTube DJ 音乐视频的生产流水线。

## 1. 定位

- **形态**：本地运行，通过浏览器（Web UI）管理。素材不上传到云端。
- **阶段性策略**：先作为自用生产工具，用它运营 1–2 个音乐频道来验证效果，再考虑产品化（比如面向 DJ 的桌面工具）。
- **目标用户（产品化之后）**：DJ 和音乐制作人、不露脸音乐频道的运营者、活动和夜店回顾视频的制作方、AI 音乐（Suno 等）创作者。

## 2. 核心洞察

好的 DJ 卡点视频取决于三点，"切点对拍"只是基础：

1. **剪辑密度跟随音乐能量**：铺垫段切得稀，drop 段每拍甚至每半拍切一次。
2. **画面里的动作对拍**：片段中运动或亮度峰值的时刻要落在强拍或底鼓上。
3. **相邻镜头连贯**：色调、运动、主题要接得上。

### 术语

| 术语 | 定义 |
|---|---|
| 素材（Video） | 用户上传的原始视频 |
| 片段（Clip） | 转场检测切出来的镜头，**只记录入点和出点，不物理切割原文件** |
| 视觉节拍（visual beat） | 片段里运动或亮度突然变化的时刻 |
| 节拍偏移（beat offset） | 片段里最强的视觉节拍距离片段入点的时长（秒） |
| 能量等级（energy） | 音乐每个小节的能量分档（low / mid / high） |
| 时间线（Timeline） | 编排结果：一组按顺序排列的（片段、入点、时长），JSON 格式 |

## 3. 功能 1：素材入库流水线

1. Web 上传视频，后台任务队列处理。
2. 用 ffprobe 读取元数据（时长、分辨率、帧率、编码）。
3. 生成低码率代理文件（proxy）和封面缩略图，供 Web 端流畅预览。
4. 转场检测，切成片段：
   - P0 用 PySceneDetect（AdaptiveDetector），方便在频闪素材上调参。
   - P1 换成 TransNetV2，对渐变和闪光更稳。检测器是可插拔接口。
5. 片段特征：
   - 本地基础特征：运动强度曲线、平均亮度、饱和度、主色调、清晰度、视觉节拍峰值和偏移。
   - 本地语义特征（P1）：CLIP/SigLIP 向量，支持文本搜索。
   - 付费 API 语义标签（P1）：每个片段抽 3–4 帧拼成一张图，交给 Claude 或 Gemini，输出结构化 JSON（场景、元素、情绪、能量、适合放在哪类段落），结果缓存。
6. 质量与去重（P1/P2）：感知哈希去重、OCR 检测水印和字幕、黑边检测。
7. 人工校正（P1）：合并或拆分片段、修改标签、禁用片段。

## 4. 功能 2：音乐分析与自动编排

### 4.1 音频分析（全部本地）

| 数据 | 方案 |
|---|---|
| 节拍、小节第一拍、BPM | `beat_this`（主），librosa（备用，没有小节第一拍时按 4/4 推算） |
| 段落结构（P1） | `allin1`（intro/verse/chorus/drop 等） |
| 鼓点（P1） | `demucs` 分离出鼓轨，再做 onset 检测 |
| 能量曲线 | 按小节计算 RMS，再按分位数分成 low/mid/high 三档 |

### 4.2 编排（两层）

- **剪辑层（算法，P0 起）**：
  - 根据能量决定切点间隔：low = 2 小节，mid = 1 小节，high = 2 拍（可配置）。
  - 为每个切点空位给候选片段打分：
    `能量匹配 + 时长适配 + 视觉峰值能否对齐 + 和上一个镜头的连贯度 − 重复惩罚 + 是否符合主题`
  - 贪心选择（P2 再考虑束搜索）。时长不够时允许 0.8–1.25 倍的轻微变速（P1）。
- **导演层（LLM，P2）**：输入音乐结构和素材库的标签摘要，输出每一段的编排意图（主题、情绪、剪辑密度）。导演层只做高层决策。

### 4.3 时间线编辑与输出

- 时间线 JSON 是唯一的事实来源。Web 时间轴上可以查看，并一键"换一个候选片段"（P1）。
- 渲染：FFmpeg，优先用 NVENC 硬件编码（h264_nvenc），不可用时退回 libx264。为避免累计漂移，切点按帧数累计计算。
- 导出 FCPXML 或 EDL，交给 DaVinci 或 Premiere 精修（P2）。

## 5. 技术架构

```
浏览器 (原生 HTML/JS，无构建步骤)
   │  REST / 静态文件
FastAPI ── SQLite (元数据)
   │
后台任务队列（单 worker 线程，GPU 任务串行执行）
   ├─ ingest:  ffprobe → proxy/缩略图 → 转场检测 → 片段特征
   ├─ music:   节拍/小节第一拍 → 能量
   ├─ compose: 编排算法 → timeline JSON
   └─ render:  FFmpeg 分段编码 → concat → 合成音轨
```

- 运行环境：conda 环境 `vid-scenes`（Python 3.11）。
- 硬件基线：i7-14650HX、64GB 内存、RTX 4060 Laptop（8GB 显存）。
- 素材量级：初期几十个视频，后期几百个。SQLite 足够；向量检索直接用 numpy 暴力计算，不引入专门的向量数据库。
- 数据目录：`data/`（不纳入版本控制）
  - `data/app.db`
  - `data/videos/{id}/`：原文件、代理文件、缩略图
  - `data/music/{id}/`：音频、分析结果
  - `data/renders/{id}/`：成片

## 6. 付费 AI API 使用原则

- 用在语义理解（片段标注）和高层决策（导演层），每个片段或每首歌只调用一次，并缓存结果。
- 节拍和转场检测不用 API，本地模型更准也更便宜。
- 生成式视频补齐素材缺口，留到后期。

## 7. 风险与合规

- **YouTube 对重复或批量内容的政策**：全自动、模板化、大量产出的视频有限制变现的风险。保留人工精修环节（时间轴编辑、导出精修）。
- **音乐版权**：Content ID 会把收入划给版权方。优先使用有授权的音乐或自有作品。
- **素材版权**：在素材上记录来源和授权信息（P1 加字段）。

## 8. 长曲产品线（DJ Mix，30–90 分钟）

和单曲共用素材库和分析引擎，在此基础上新增三个模块：

1. **曲目拆分**：优先导入 tracklist 或 cue 文件（rekordbox、Serato 导出），没有时再自动识别（BPM 变化、频谱突变、混音过渡段）。每首曲目单独做节拍分析，过渡段特殊处理。
2. **宏观编排**：LLM 根据整个 mix 的能量曲线规划每首曲目的视觉主题；每首曲目一个素材池。
3. **分块渲染**：按曲目并行渲染后无损拼接，支持断点续渲和单首重渲；先出低分辨率预览。

应对素材不足的方法：慢段用长镜头降低切点数量、设定最小重复间隔、派生变体（镜像、倒放、变速、裁切、调色）、叠加音频驱动的 VJ 层。

附带产出：YouTube 章节时间戳、曲目名字幕、封面候选。

架构要求：编排引擎可插拔。单曲编排器就是长曲编排器里的"单曲目"特例。
