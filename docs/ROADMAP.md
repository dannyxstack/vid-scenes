# MVP 路线图

状态标记：⬜ 未开始 · 🟨 进行中 · ✅ 完成

## P0：端到端跑通（单曲）✅

目标：上传素材 → 自动切片 → 上传音乐 → 一键生成卡点视频，全程在 Web 上完成。

| # | 功能 | 验收标准 | 状态 |
|---|---|---|---|
| 0.1 | 项目骨架：FastAPI + SQLite + 后台任务队列 + 静态前端 | 启动后能打开首页；任务状态可以查询 | ✅ |
| 0.2 | 视频上传与元数据 | 上传后能看到时长、分辨率、帧率 | ✅ |
| 0.3 | 代理文件与缩略图 | 列表显示封面；点击能流畅播放代理文件 | ✅ |
| 0.4 | 转场检测切片（PySceneDetect） | 片段列表显示每个片段的缩略图和入点、出点；能播放单个片段 | ✅ |
| 0.5 | 片段基础特征 | 每个片段有运动强度、亮度、饱和度、主色调、清晰度、视觉峰值偏移 | ✅ |
| 0.6 | 音乐上传与分析 | 显示 BPM、节拍和小节第一拍、按小节的能量等级；波形图上标出节拍 | ✅ |
| 0.7 | 规则编排 | 根据能量决定切点间隔，按打分贪心选片段，生成时间线 JSON | ✅ |
| 0.8 | FFmpeg 渲染 | 输出 1080p 的 mp4，切点和节拍误差不超过 1 帧，可以在 Web 上播放和下载 | ✅ |
| 0.9 | 测试 | 用合成视频和合成节拍音轨跑通端到端测试 | ✅ |

不在 P0 范围：语义标签、文本搜索、手动编辑时间线、特效、变速。

### P0 实现备注

- 视觉峰值对齐已经有基础版：片段第一次被使用时，会把它的视觉峰值放在切点上。P1 再细化成对齐底鼓。
- 节拍分析的健壮性处理：小节第一拍会吸附到最近的拍上；离上一个强拍不足 3 拍的伪强拍会被去掉；每小节拍数不合理时按 4/4 重新推算。
- 编排约束：相邻镜头不能用同一个片段（硬约束）；短于 0.3 秒的镜头并入前一段。
- 尚未用真实素材和真实音乐做主观质量验收。这是进入 P1 之前的第一件事。

## P1：质量与可控性 ⬜

- TransNetV2 转场检测（可插拔，可选）
- CLIP/SigLIP 向量 + 文本搜索素材
- LLM 片段标签（Claude 或 Gemini），结果缓存
- `allin1` 段落结构；demucs 鼓轨分离和 onset
- 视觉峰值对齐强拍（入点 = 强拍时间 − 偏移量）
- 轻微变速补齐时长
- Web 时间轴编辑器：查看、替换片段，锁定片段后重新编排
- 片段人工校正：合并、拆分、禁用、改标签
- 素材来源和授权字段

## P2：风格化与交付 ⬜

- 导演层 LLM（编排意图）
- 节拍触发特效：闪白、缩放冲击（zoom punch）、抖动、RGB 分离
- 风格预设（techno、house、future bass、phonk）
- 导出 FCPXML 或 EDL
- 9:16 智能裁剪
- 从用户的替换操作中学习，调整打分权重
- 感知哈希去重、OCR 检测水印和字幕
- 束搜索编排
